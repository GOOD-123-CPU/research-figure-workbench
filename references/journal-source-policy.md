# Journal and Conference Requirement Source Policy

Publisher requirements change. Treat source quality and submission phase as first-class data.

## Evidence classes

Use the strongest available source and label its class.

- **A — Official current rule**: publisher/journal author guide, artwork instructions, submission portal, production specification, or official society/conference instructions.
- **B — Official general guidance**: publisher-wide or society-wide guidance that may be overridden by the exact venue/article type.
- **C — Scientific/technical best practice**: peer-reviewed visualization, accessibility, statistics, or imaging guidance.
- **D — Community/editorial practice**: public examples, experienced-author conventions, repositories, templates, editor anecdotes, or reverse-engineered visual patterns.

Never describe C/D guidance as official journal policy.

## Stage matters

Record the stage because initial submission and production-ready artwork may differ:

- initial submission / peer review;
- revision;
- accepted-in-principle / production;
- supplementary / extended data;
- web-only interactive or data supplement.

Do not import a final-production requirement into an initial-submission workflow unless it is useful as a forward-compatible choice.

## Verification record

For every venue-specific rule that materially affects output, record:

```text
Rule ID:
Rule:
Venue/article type:
Submission phase:

```

## Resolution order for conflicts

1. Exact journal/conference + exact article/track + current stage.
2. Publisher/society general instruction.
3. User-provided editor/production instruction specific to the manuscript.
4. Scientific best practice.
5. Community examples/style preference.

A manuscript-specific editor or production instruction can supersede a generic publisher default, but preserve the instruction in the project record rather than treating it as a universal rule.

## Offline rule

If live official verification is unavailable:

- use neutral bundled defaults;
- label venue-specific assumptions `UNVERIFIED`;
- do not claim compliance;
- provide the exact items the author should verify before upload (dimensions, fonts, file format, raster resolution, color mode, legends/captions, source data, AI-image rules, and any figure-count limits).

## AI-generated artwork policy

Policies for generated or AI-edited images vary and change quickly. Before using generative-image output in a manuscript figure or graphical abstract:

1. verify the exact target venue's current policy;
2. distinguish quantitative evidence from conceptual artwork;
3. preserve provenance and disclosure information;
4. require human scientific review;
5. mark output as a draft until eligibility is verified.

Never use generated imagery to fabricate or replace experimental evidence.
